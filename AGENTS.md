# AGENTS.md

High-signal context for OpenCode sessions in this repo.

## Workflow

- **Every change must be made on a new branch.** Never commit directly to `main`. Create a dedicated branch for each task and open a PR from it.
- **Keep `README.md` up to date.** Whenever you add, change, or remove user-facing behavior (CLI flags, Web-App features, pipeline steps, parameters/defaults), update `README.md` in the same change so it never drifts from the code.

## Setup

- **Python 3.13 strictly required.** `manifold3d` and `pymeshfix` have no wheels for 3.14 yet.
- Runtime deps live in `requirements.txt`, test-only deps in `requirements-dev.txt` (which includes the former via `-r`). `scikit-image` is a runtime dep despite never being imported directly: `trimesh` imports it lazily inside `matrix_to_marching_cubes`, so pip won't pull it in on its own. Don't "clean it up".
- No linters or build system are configured. Do not invent them unless asked. `pyrefly.toml` is checked in for local type checks (`pyrefly check`), but it is deliberately **not** part of CI — keep it that way unless asked.
- **The runtime image must ship `.streamlit/config.toml`.** The Dockerfile copies files individually (not `COPY . .`), and the pinned dark theme lives in that file. Without it the container falls back to the light theme while the custom CSS in `app.py` stays dark-tuned — sidebar labels then render unreadable. Any new file the app reads at runtime has to be added to the `runtime` stage explicitly. **The same holds for the `test` stage:** it copies its files individually too, so a repo file the tests read has to be named there *and* must not be excluded by `.dockerignore` — which is why the `Dockerfile` deliberately stays in the build context (`tests/test_streamlit_config.py` reads it). Miss one and the tests pass locally but fail inside the image.

## Testing

- A `pytest` suite lives in `tests/` (config validation, each pipeline step, `app_helpers`, end-to-end, CLI). Run with `pytest` (full suite ~70 s) or `pytest -m "not slow"` to skip subprocess/CLI tests and the finest-pitch geometry runs.
- **Never test a re-implementation of shipped code.** If a helper is hard to import, move it somewhere importable (see `app_helpers.py`) instead of copying its body into the test file — a copied test passes even when the real function is broken.
- **After every code change, run the tests.** If the suite fails, fix the regression before considering the change done.
- **Extend the suite when you add or modify behavior.** New functions, new branches, new edge cases or bug fixes must come with matching tests. Keep test docstrings and comments in English per the language convention below.
- Shared fixtures (cube/sphere STL, fast config) live in `tests/conftest.py` — reuse them instead of regenerating geometry.
- **Geometry changes are tested by measuring the output mesh, not by re-checking a formula.** `tests/geometry_probe.py` measures a finished inlay independently of the pipeline (pocket bounds against the box, `min_gap` between pockets, ray casts, shell count); `tests/test_geometry_invariants.py` pins the invariants with it (walls = `wall_thickness`, wall between cavities = `figure_gap`, every figure has its own pocket, no sealed void, no recess breakthrough). The old suite asserted `h == wall + df * ...` and stayed green through every one of those bugs.
- **CI is `.github/workflows/tests.yml`** (pull requests and pushes to `main`): one job runs `pytest` on a plain runner with Python 3.13, a second builds `docker build --target test .` and then the `runtime` stage with a smoke test (imports + `/_stcore/health`). `tests/test_streamlit_config.py` also checks statically that the runtime stage copies `app.py`, every repo module it imports and `.streamlit/` - stage by stage, because a whole-file search was satisfied by the test stage alone. The Docker job is not redundant — it is what catches a version pin that no longer resolves on `python:3.13-slim` and a new source file missing from the Dockerfile's explicit `COPY` list. Its very first run proved the point: `.streamlit/` and the `Dockerfile` were missing from the `test` stage, so `docker build --target test .` had been failing four tests in `test_streamlit_config.py` while the same suite was green locally. Adding a source file therefore means touching the Dockerfile in the same change, or CI goes red. The pytest job deliberately installs no apt packages: no runtime wheel links against libGL or libglib (checked with `ldd`), the Dockerfile needs them only because the slim image ships with almost nothing.

## Language convention

- **All comments and docstrings in the code are written in English.** This
  applies to every source file, tests included — the repository is published
  publicly, so contributors who do not read German have to be able to follow
  the reasoning in the code.
- **UI copy is not affected.** User-facing text lives in `i18n.py` and is
  bilingual (English/German) by design; do not "translate" it into the code.
- Parts of the existing codebase still carry German comments from before this
  convention. Convert them to English as you touch the surrounding code — do
  not start a separate blanket translation pass unless asked.

## Architecture

- `inlayer.py` is the pipeline library module. It exposes a frozen `Config` dataclass plus pipeline functions (`apply_euler_rotation`, `prepare_figure`, `dilate`, `build_inlay`, `wall_thickness_stats_3d`; `arrange_footprints` is the layout `build_inlay` uses). All parameters flow through `Config`.
- `app_helpers.py` holds the **Streamlit-free** helpers of the web app (`file_hash`/`bytes_hash`, `quantize_axis_value`, `resolve_selection`, `applied_figure_params`, `figure_labels`, `load_preview_mesh`, `preview_copy`, `scene_layout`, `selection_key`, plus `decimate_mesh` re-exported from `inlayer`). `app.py` imports and thinly wraps them (caching decorators, session-state lookups). Reason: `app.py` calls `st.set_page_config()` and builds the whole sidebar at import time, so it cannot be imported in tests — anything pure belongs in `app_helpers.py` so the suite tests the shipped code instead of a copy. Do not re-inline this logic into `app.py`. (`tests/test_app_render.py` does run `app.py` through Streamlit's `AppTest`, which catches render errors — but that is an integration check, not a licence to move logic back into the frontend.)
- `app.py` is a Streamlit frontend. It builds an `inlayer.Config` from the sidebar widgets and passes it into the pipeline functions (no global mutation). Its widgets start at `Config`'s defaults (`inlayer.Config.<field>`, read the way the CLI reads them), never at literals of their own: `tests/test_app_render.py` checks that both entry points start from the same values.
- `i18n.py` holds the **bilingual UI** (English/German). `t(key, **kwargs)` looks up `TRANSLATIONS` and fills named placeholders; unknown keys return the key itself rather than raising, so a missing string can never abort a running computation. Keys are namespaced `app.*` / `cli.*` / `pipeline.*` / `config.*` / `error.*` / `check.*` (wall-check findings, shared by CLI and app through `inlayer.describe_violation`).
- **The current language is a `ContextVar`, not a module global.** Streamlit runs each session's script in its own thread; a shared global would let one session's language selection bleed into another's. Do not "simplify" this into a plain variable.
- **`ThreadPoolExecutor` workers do not inherit ContextVars.** `_parallel_map` captures the language before submitting and re-applies it inside each worker — without that, parallel steps log in the default language. `tests/test_i18n.py` pins this behaviour *and* the assumption behind it. Any new thread pool that logs needs the same treatment.
- **In `inlayer.py` the translation function is imported as `t_`, not `t`.** `t` is used throughout the module as the timestamp returned by `_log()`; importing the translator under that name shadows it and fails at runtime with `'float' object is not callable`.
- **`app.py`'s "all figures" sentinel stays untranslated.** `ALL_FIGURES` is a stored session-state value, not display text — translating it would invalidate the saved selection on a language switch. It is rendered through `format_func` (`_fig_label`) instead. The same applies to any option value that is persisted rather than merely shown - the figure options are upload ids for the same reason.
- **Every widget in `app.py` has a fixed, language-independent `key`.** Streamlit derives an unkeyed widget's identity from its label, which is translated: a language switch created new widgets, the uploads vanished and every setting fell back to its default. `tests/test_app_render.py` fails on a widget call without `key=`.
- **Per-figure settings belong to an upload (`UploadedFile.file_id`), not to a file name.** `fig_offsets_dict` is keyed by id; entries of removed uploads are deleted (re-uploading starts from the defaults), duplicate names are shown as `model.stl (2)` (`figure_labels`). Two different `model.stl` files used to share one entry and moved together.
- **Selections and sliders are reconciled with the uploads before any widget exists.** All three per-figure controls (recess position, offsets, rotation) resolve their selection through `app_helpers.resolve_selection` and reload their widgets from the stored values whenever the figure they show changes - including a removed upload, a new first figure under "all figures" and widget state dropped while hidden. Don't go back to loading in the selectbox `on_change` only: that missed every change to the file list, and the sliders then showed values the pipeline did not use.
- **`app_helpers.applied_figure_params` is the only source of per-figure values.** The run, the instant preview and the staleness snapshot all read it - never a slider, which only shows the selected figure (reading the slider made a mere selection change look like a settings change).
- **New user-facing text needs both languages.** `tests/test_i18n.py` fails on a missing translation, on placeholders that differ between languages, on positional `{}` placeholders, and on keys referenced in source but absent from the table.
- **Finger recesses** (`Config.enable_finger_recesses`, `Config.finger_radius`) are exposed in the Web-App and via the CLI flags `--finger-recesses` / `--finger-radius`. `build_inlay` communicates results back through `inlay.metadata`: `wall_check` (the full check, see below), `violating_indices` (figures with at least one finding), `placements` (per figure, the translation applied to the mesh passed in) and `finger_recesses` (recess meshes for the preview).
- **Two different knobs move the recesses.** `finger_recess_z_offset` (mm) sinks them below the box's top edge; `finger_recess_position` (`-1.0` … `1.0`) slides the pair *along* the figure, across `finger_recess_axis`, to pick the grip point. The latter is relative to the figure's usable half length (half extent minus `finger_radius`), not mm: one setting then fits figures of different sizes and `±1.0` keeps the hemisphere within the figure's own length. (Across that axis a figure narrower than `2 × finger_radius` is still exceeded by the recess - the box and the layout see it, because they are measured on the cutters.) The silhouette search band is centred on that grip position, so the recesses hug the figure where the fingers actually reach in. **The grip position is per figure** (`build_inlay(individual_recess_positions=[...])`, one value per figure, falling back to the config value where an entry is missing; Web-App: selection above the slider, stored per upload in `fig_offsets_dict`; CLI: `--finger-recess-position` takes one value or one per `-i` file). Radius, axis and Z offset stay global on purpose — they describe the hand, not the figure. The app's per-figure state init therefore sits directly after the file uploader: the recess controls are rendered further up the sidebar than the manual offsets and already need `fig_names`.
- **`build_inlay` arranges, dimensions and checks - from the real cutters.** Each figure sinks `depth_fraction` of its *own* height below the box's top face (a short figure next to a tall one used to get no pocket at all; an STL's absolute Z decided the box height). Its voxel solid plus its recesses form its cutter; `arrange_footprints` spaces the cutters' XY footprints exactly `figure_gap` apart, the box adds `wall_thickness` around them and below the deepest one. Voxelization shifts a cavity by up to half a pitch depending on where it lies on the grid - any box sized from a *predicted* inflation (the old `clearance + voxel_pitch` / `voxel_pitch/2` pads) was off by that much. So: solidify first, measure, then place. Don't reintroduce caller-side box bounds (`stable_global_bounds` / `arrange_with_stable_bounds` are gone on purpose) or inflation constants.
- **Manual offsets move a figure inside a fixed box.** The box is dimensioned before `individual_offsets` are applied; walls an offset makes too thin are findings of the wall check, not a reason to grow the box.
- **The layout follows the rotated figures; the unrotated ones only fix the order.** The app passes them as `sorting_reference`, so neighbours don't swap places while one figure is being rotated. Laying out the unrotated figures (the old "stable slots") let rotated cavities overlap by 18 mm with a green badge.
- **Cutters end `CUT_OVERSHOOT_MM` above the top face.** `_solidify_figure(..., top_z)` fills every column up past the top face (a figure ending below it left a sealed void), the recess template is a hemisphere with a vertical shaft (a lowered bare hemisphere had a roof). The automatic box height also keeps `wall_thickness` below the deepest recess.
- **`inlay.metadata["placements"]` is what the preview draws with.** The prepared figure shares its frame with the dilated one passed to `build_inlay`, so `fig.apply_translation(placements[i])` puts it exactly into its cavity. Don't re-derive the placement in the app.
- **The wall check is exact and per figure (`_wall_check`).** Each cutter is clipped to the box with manifold3d: side and floor walls come from the pocket's bounds (for the cylinder: apothem minus the farthest vertex), walls between pockets from `min_gap`, sealed voids from negative-volume shells. Findings (`side`, `floor`, `inner`, `merged`, `sealed`, `no_cavity`) carry the figure index. `passes_min_wall` means *no finding at all*; `WALL_TOLERANCE_MM` (0.05) only absorbs float32 rounding and the cylinder's chord error. `wall_thickness_stats_3d(inlay)` just reports it - there is no voxel fallback for meshes that did not come out of `build_inlay`.
- **`build_inlay` never rotates.** Rotations are applied in step 1 via `apply_euler_rotation` and are already baked into the meshes handed to `build_inlay`. It used to accept an `individual_rotations` argument that was silently ignored — that parameter is gone; don't reintroduce it.
- There are **two entry points:**
  - CLI: `python inlayer.py [-i figure.stl] [-o inlay.stl] [-c 0.4] [--lang de] …` — `--lang` is parsed *before* the main parser is built, because argparse renders help strings at construction time; `INLAYER_LANG` is the fallback.
  - Web UI: `streamlit run app.py`

## trimesh 4.x quirk

- `VoxelGrid.marching_cubes` does **not** apply the grid transform to vertices; the mesh has to be `apply_transform`ed manually afterwards or it comes out misaligned. **Go through `_grid_to_mesh(matrix, transform)`** — it is the single place that knows this, and the only `marching_cubes` call in the codebase. Don't call `marching_cubes` directly.
- **`_padded_transform(transform, iters)`** does the matching correction for an `np.pad` of `iters` voxels per side. `iters=0` is a no-op copy, so padded and unpadded paths can share one call.

## Algorithmic choices

- **Voxel dilation** is used for the tolerance offset (`dilate`) instead of normal-shifted surface offset. This is intentional: voxel offsetting survives cracks and non-manifold edges that vertex-normal offsets choke on.
- **Voxel inflation is compensated in `dilate`.** Marching cubes inflates surfaces: ~`voxel_pitch/2` per side in `prepare_figure` plus ~`voxel_pitch/4` in `dilate`'s own reconstruction. Measured surplus without compensation: `0.75 * voxel_pitch`, geometry-independent (cube == sphere, 2026-07). `dilate` subtracts this from the requested distance; consequence: the effective clearance cannot drop below ~`0.75 * voxel_pitch`.
- **The dilation is (nearly) isotropic.** scipy's default element (6-neighbourhood) grows an octahedron - 2 mm of clearance along the axes left 1.5 mm on a 45° slope. `dilate` does a share of `(√3 − 1)/2` of its steps with the full 3×3×3 cube, which makes axis and space-diagonal growth equal (every direction within 0.97–1.06). The growth *along the axes* stays one voxel per step, so `_dilation_iterations`' calibration holds. There is deliberately no `binary_closing` before the dilation: dilating a closing with the same element equals dilating the input (bit for bit), it only cost time.
- **Pad voxel grids before morphological ops.** scipy's `binary_closing`/`binary_dilation` clip at array borders — without `np.pad` by the iteration count, the erosion step eats the figure's extremes (a sphere literally turns into a cube at coarse pitch). Both `prepare_figure` and `dilate` pad and then correct the grid transform for the padding offset.
- Boolean CSG runs in manifold3d, never in trimesh's default engine: `build_inlay` calls `manifold3d` directly (`_to_manifold`/`_to_trimesh`, the same float32 conversion `trimesh.boolean` uses with `engine='manifold'`), because the wall check needs the `Manifold` objects anyway.

## Runtime notes

- Voxel pitch (`Config.voxel_pitch`) trades resolution for memory non-linearly (O(n³)). Halving the pitch increases memory ~8×.
- **Keep voxel operations vectorized.** Per-voxel work goes through numpy/scipy (`binary_closing`/`binary_dilation` with `iterations=`, `argmax`/`where=`-reductions) — never Python loops over voxel grids. Avoid allocating full-grid temporaries when a reduction or mask achieves the same.
- **Reuse geometry templates.** Primitives that are identical per figure (e.g. the finger-recess template in `build_inlay`) are built once and `copy()`-translated per use — don't recreate icospheres or run boolean ops inside the per-figure loop.
- **Optional multi-threading** (`Config.enable_parallel`, CLI `--parallel`, Web-App checkbox): per-figure steps (prepare, dilate, solidify) go through `_parallel_map`, which uses a `ThreadPoolExecutor` — plain threads suffice because numpy/scipy/trimesh release the GIL during C calls. Workers are capped at `MAX_PARALLEL_WORKERS = 4` because concurrent voxel grids multiply peak memory (O(n³)). `app.py` uses the same `_parallel_map` and attaches the Streamlit ScriptRunContext through its `worker_init` hook (needed for `st.cache_resource` in worker threads) - it used to run its own pool, which skipped the language hand-over.
- **`fast_simplification` is not thread-safe — decimate only through `inlayer.decimate_mesh`.** Its `simplify()` loads the mesh into process-global C++ state (`load` → `simplify` → `return_points`), so two concurrent calls hand *both* callers the mesh that was loaded last. With `--parallel` this produced an inlay whose cavities were all the same figure. `inlayer.decimate_mesh` serializes every call behind `_SIMPLIFY_LOCK`; `app_helpers.decimate_mesh` is a re-export of it. `trimesh.simplify_quadric_decimation` is a thin wrapper around the same library — calling it directly reopens the hole. (The bug only surfaced once `prepare_figure` started skipping `pymeshfix` for clean meshes: the repair step used to stagger the threads by seconds.)
- In `app.py`, expensive preview decimation must go through the cached `_decimated_for_viz(mesh, cache_key, face_count)` with a stable cache key, so Streamlit reruns don't re-decimate. It returns `app_helpers.preview_copy`, a geometry-only copy: under the face budget `decimate_mesh` returns its input, and the process-wide cache then held whole meshes with their metadata. The result stored in the session keeps only what the view reads (decimated inlay, placements, recesses, stats).
- **Keys of process-wide caches identify the cached object by content, never by name or size.** `st.cache_resource` is shared by every session in the process: keyed by `name:size`, a second user uploading a different `model.stl` of the same size saw the first user's model. Uploads are identified by their content hash (`content_hashes[uf.file_id]`, computed once per upload); a cached figure's key carries everything that determines it (content hash, scale, pitch, decimation, rotation) - the inlay's hash does not determine a figure.
- **Never repair with pymeshfix's defaults.** `MeshFix.repair()` defaults to `remove_smallest_components=True`, which keeps only the shell with the most triangles: a holed figure lost its separate base (or, sorted by triangle count, its body). `prepare_figure` passes `remove_smallest_components=False`.
- **Raw input meshes are voxelized through `_voxelize_surface`, never `mesh.voxelized()`.** trimesh's voxelizer subdivides until every edge is below `pitch / 2`, so its cost grows with edge length² - a low-poly CAD rod took 1.95 GB, a 250 mm bar aborted. `_voxelize_surface` samples triangles in rows and scales with area. `dilate` and `_solidify_figure` may keep `mesh.voxelized()`: they voxelize marching-cubes output with edges of about one pitch. `_check_grid_size` refuses grids above `MAX_GRID_VOXELS` before anything is allocated.
- **Streamlit drops a widget's state while the widget is not rendered.** Values that must survive a hidden section live in plain session keys and the widget only writes through to them (`app._select`); otherwise hiding the rotation section reset the step to 45° and a stored 350° crashed every rerun. **Streamlit 1.62 also sends a selectbox value as its label**, so after a language switch the old label matches no option: every selectbox with translated labels goes through `_select` (raw value in a plain key, labels resolved once per run, unknown values map to no label). A lenient `format_func` (`"x" if a == "x" else <y label>`) turned the stale label into the value `"left/right"` and crashed the next run.
